# ArchiveFS v0.7.0-alpha release notes

Status: RC1 candidate artifact built, verified, and proven byte-for-byte
reproducible on branch `feature/gui-navigation-reset`. No Git tag exists
yet, no GitHub Release has been created, and no artifact has been
published anywhere - this document records validation results, it is not
itself a publication.

## 1. Overview

v0.7.0-alpha is a release candidate that adds a new default, beginner-first
navigation shell (Gamer View) alongside the existing full-capability Advanced
View, direct game-image discovery, platform-first shared navigation, a
visual platform-artwork picker, Dolphin and Xenia Canary cheat/patch
install-and-rollback workflows, PCSX2 adapter foundations, a read-only
cheat-provider coverage audit command, and a dependency-security
remediation that resolves every previously outstanding RustSec advisory.
It does not add ROM/BIOS distribution, gameplay emulation, or automatic
cheat installation of any kind - every write path remains explicit,
previewed, and confirmed.

## 2. Major user-visible changes

- **Gamer View is now the default screen** on first launch: search,
  platform picker, game list, and a selected-game action panel, with a
  clear path to Advanced View for every existing capability.
- **Advanced View preserves everything** that existed before this release -
  Library, Mount, Active Mounts, Sources, History & Logs, Settings, Doctor,
  and the full Cheats & Mods workflow. Nothing was removed to make room for
  Gamer View.
- **A visual platform picker** with small original vector artwork replaces
  the previous plain text platform filter chips.
- **A new read-only coverage audit command** (`archivefs-cli
  cheat-provider-coverage`) lets you check, for specific games you choose,
  how much of your existing local Dolphin/RetroArch cheat catalogue
  actually applies - without installing anything.
- **All previously outstanding dependency-security advisories are
  resolved** (see §11).

## 3. Gamer View improvements

Gamer View is one screen: a search box and platform picker on the left
above a full-height, independently scrolling game list, and a fixed
selected-game action panel on the right. Selecting a game immediately
populates the panel with a clear primary action (Mount, or "no mounting
needed" for direct-image formats like RVZ/ISO), followed by secondary
actions (Cheats & Mods, Details, Open location) and, only when a genuinely
reversible operation exists for that exact game, Undo. Selected rows are
visually emphasized (bold text plus a drawn selection border). Cheats & Mods
opens already scoped to the selected game - no separate archive picker - and
has an explicit "Back to games" action. A small gear menu (not a permanent
top-level control) is the only way into Advanced View from Gamer View;
Advanced View always shows a clear, always-visible "Return to Gamer View"
action.

## 4. Platform artwork behaviour

Built-in platform artwork is original ArchiveFS project artwork - abstract
geometric shapes, never a reproduction of any manufacturer's logo or product
design - stored as SVG source files under
`crates/archivefs-gui/assets/platforms/` for licensing clarity, and rendered
in Gamer View as small native vector glyphs (not a rasterized copy of the
SVG content; see [`docs/PLATFORM_ARTWORK.md`](../PLATFORM_ARTWORK.md) for
exactly why). A closed set of category fallbacks (console, handheld,
computer, arcade, optical-disc, cartridge, unknown) covers every platform
without dedicated artwork - not every platform has (or needs) a unique
image.

An optional custom-artwork directory (Advanced View → Settings → "5.
Platform artwork") can override the built-in glyph with your own local PNG
file per platform id (`gamecube.png`, `ps2.png`, etc.). Decoding is
bounded (maximum 1 MiB file size, 1024x1024 pixel dimensions, 4 MiB decoded
allocation), PNG-only, and any rejection or malformed file falls back to the
built-in glyph automatically - artwork is never the only way to identify a
platform; the name and count remain visible regardless. **No artwork of any
kind is ever fetched over the network.**

## 5. Dolphin cheat support

Dolphin cheat discovery and application have been manually proven this
release cycle: exact Game ID identity from the bounded disc-header reader,
region and revision checked as part of matching, and Gecko definitions
distinguished from Action Replay content (only Gecko is ever installed
through the approved provider path). Installation goes through the shared
transaction engine - explicit preview, confirmation, verified backup before
any replacement, a written journal, and preview-then-confirm rollback.
**Catalogue coverage is not universal**: it depends on what the official
upstream Dolphin `GameSettings` dataset actually contains for a given exact
Game ID, region, and revision, not on ArchiveFS's own matching logic being
weakened. See [`docs/CHEAT_PROVIDER_COVERAGE.md`](../CHEAT_PROVIDER_COVERAGE.md)
for the specific reasons a Dolphin lookup can honestly return zero matches.

## 6. RetroArch cheat support

RetroArch cheat discovery and application have been manually proven this
release cycle, using the existing candidate matcher's strongest-evidence-wins
model (exact serial/hash, then exact normalized title+platform+region, down
to weak filename-only evidence). **Ambiguous, tied candidates are rejected,
not guessed** - if two or more catalogue entries match equally well, none is
silently selected. Platform, identity, region, and revision evidence remain
real safety inputs to matching, not just informational fields. Catalogue
coverage is not universal; ordinary `.cht` files commonly lack explicit
region/revision fields at all, and that absence is reported honestly rather
than treated as proof of compatibility.

## 7. PCSX2 adapter status

This release adds real PCSX2 adapter foundations to `archivefs-core`:
verified executable-CRC identity (with optional serial/region constraints),
bounded profile discovery, a strict PNACH parser and safe managed-block
renderer, and a transaction-backed install/Undo path with the same
backup/journal/rollback guarantees every other adapter uses - proven by an
automated end-to-end test suite using disposable fixtures only.

**This capability is not yet reachable by an end user.** The GUI's PCSX2
workflow still shows "installation unavailable" (this release only added
recognition wiring so Cheats & Mods knows a PS2 archive routes to PCSX2),
and there is no CLI subcommand for PCSX2 install yet. **No approved
downloadable ordinary-cheat catalogue is bundled** - the official
`pcsx2_patches` repository primarily distributes widescreen/no-interlace
patches, not an ordinary-cheat source, so ArchiveFS makes no PCSX2
gameplay-support claim in this release.

## 8. Read-only cheat-provider coverage audit

`archivefs-cli cheat-provider-coverage --id <archive-id>... [--json]` audits
at most 32 exact, explicitly chosen archive IDs against your existing local
Dolphin and RetroArch catalogues. It opens the library database read-only,
never scans your whole library, and never installs, enables, copies,
renames, or edits anything. The report gives compatible/rejected/
duplicate/conflict/unsupported counts and honest no-match reasons, and
intentionally omits archive paths, catalogue paths, profile paths, tokens,
credentials, and local usernames. See
[`docs/CHEAT_PROVIDER_COVERAGE.md`](../CHEAT_PROVIDER_COVERAGE.md) for the
full model, including exactly what a coverage gap can and cannot mean for
each provider.

## 9. Safety and rollback guarantees

Every install path in this release (RetroArch, Dolphin) shares one
transaction engine: explicit preview before any write, a separate
confirmation step, a verified backup taken before any existing file is
replaced, a written journal recording the exact operation, and
preview-then-confirm rollback that restores exact prior bytes or removes a
newly-created file. This release specifically hardened two cross-cutting
safety properties surfaced by manual QA:

- An in-flight Cheats & Mods transaction (`Applying` state) is no longer
  dropped merely because a different page becomes visible - only a
  genuinely stale transaction (a different archive, adapter, profile, or
  key) is still reset.
- A rollback preview or review in progress now survives navigating between
  Gamer View and Advanced View, rather than being silently reset the moment
  a different page renders.

Selection-generation guards and consistent focused/multi-selection clearing
across platform-filter changes prevent an async result meant for one game
from ever being applied to a different, later-selected game. Every bulk
action (Mount All, Unmount All, missing-entry removal, "Mount selected",
bulk platform assignment/clear) requires a preview and the exact item count
before confirmation, with a typed-count requirement above 25 items; Mount
All is not reachable from Gamer View at all.

## 10. Release reproducibility and artifact verification

The canonical release archive (`archivefs-v0.7.0-alpha-x86_64-linux.tar.gz`)
is built deterministically: sorted, name-only tar member order, numeric
`0:0` ownership, fixed permissions, `SOURCE_DATE_EPOCH`-derived timestamps,
and remapped compiler paths. An independent verifier checks exact archive
layout, safe extraction paths (no traversal), file types and modes,
numeric ownership, checksum validity, and the absence of private paths,
credentials, or tokens in the payload. Two independent builds from the same
commit produce byte-for-byte identical archives and checksums - see §14 for
this candidate's specific result. Full procedure:
[`docs/RELEASE_ENGINEERING.md`](../RELEASE_ENGINEERING.md).

## 12. Installation instructions

1. Download `archivefs-v0.7.0-alpha-x86_64-linux.tar.gz` and its
   `.sha256` sidecar file together (see §16 for verification).
2. Extract: `tar -xzf archivefs-v0.7.0-alpha-x86_64-linux.tar.gz`.
3. The extracted directory contains `archivefs-cli`, `archivefs-gui`,
   `install.sh`, `README.md`, `CHANGELOG.md`, `LICENSE`, and
   `config.toml.example`.
4. Run `./install.sh` or place the binaries on your `PATH` manually.
5. Run `archivefs-cli --version` and `archivefs-gui --version` to confirm
   `0.7.0-alpha`.

## 13. Upgrade notes

- A library database opened by this build is migrated forward to schema 5.
  **Older ArchiveFS builds reject that schema version** - if you need to
  downgrade, restore a pre-upgrade copy of your database first. In-place
  downgrade is not supported.
- No configuration file format changed in this release.
- If you previously used the plain-text platform filter chips, Gamer View's
  visual picker reads the same underlying platform data - no rescan is
  required.

## 14. Known limitations

- **PCSX2**: core install/Undo capability exists but is not reachable from
  the CLI or GUI yet; no approved downloadable ordinary-cheat catalogue is
  bundled; no gameplay-support claim is made.
- **Dolphin and RetroArch**: catalogue coverage is not universal and varies
  by game, platform, region, and revision evidence; ambiguous RetroArch
  matches remain fail-closed.
- **Custom platform artwork**: local PNG only; runtime SVG rendering (of
  both the built-in `.svg` source files and any custom SVG override) remains
  deferred - built-in artwork renders as a native vector glyph instead of a
  rasterized SVG.
- **Native Wayland startup** has not been manually proven in the current
  development/QA environment (only X11 was available this cycle).
- Some `egui` 0.34 deprecated compatibility entry points remain in use,
  behind a documented, explicit allowance; migrating them is deferred to a
  dedicated follow-up milestone.
- **Mount Queue's** own confirmation dialog does not yet have the >25
  typed-count escalation that Mount All, Unmount All, and the other bulk
  actions already have.
- The GUI-foundation presentation/safety modules integrated this release
  (`view_mode`, `status_wording`, `game_presentation`, `bulk_confirmation`,
  `selection_guard`) are not yet consumed by the active, already-tested
  inline Gamer View implementation.
- RVZ identity inspection is bounded and requires a readable direct header;
  unsupported layouts remain visible with an honest terminal status rather
  than being hidden.

## 15. Manual QA summary

Manual QA for this release candidate was performed against the exact
extracted release-candidate binaries (not the working-tree build), under an
X11 session (native Wayland was unavailable in the test environment - see
§14). Confirmed: GUI startup, Gamer View as the default screen, search
filtering, platform-card display and horizontal scrolling, game selection
updating the action panel with Mount as the primary action, Cheats & Mods
navigation and "Back to games", Dolphin and RetroArch cheat discovery,
PCSX2 recognition (without install), Advanced View and "Return to Gamer
View", the native file dialog, and clipboard copy/paste - all with no
crash, freeze, or rendering corruption observed. A custom-PNG artwork
override was not manually verified this cycle (no suitable PNG file was
available in the test environment); automated tests cover the valid,
malformed, and cache-invalidation PNG paths instead - see
[`docs/PLATFORM_ARTWORK.md`](../PLATFORM_ARTWORK.md).

## 16. SHA-256 verification instructions

The canonical archive's checksum is recorded in the sidecar `.sha256` file
shipped alongside it - **that sidecar file is the authoritative checksum
record**, not any copy of the digest that may appear in prose elsewhere.
Once this candidate's build is finalized, its exact digest is also recorded
here for convenience:

```text
SHA-256 (archivefs-v0.7.0-alpha-x86_64-linux.tar.gz) = 1749d470102ecbdf49a624d5b8995d18219b455d2a1cffac87602c6e99a35469
Archive size: 13,513,500 bytes | Extracted size: 37,515,485 bytes
```

To verify an archive you downloaded, run, from the directory containing both
files:

```sh
sha256sum -c archivefs-v0.7.0-alpha-x86_64-linux.tar.gz.sha256
```

A successful verification prints `archivefs-v0.7.0-alpha-x86_64-linux.tar.gz:
OK`. Do not extract or run the binaries if this check fails.
