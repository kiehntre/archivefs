# EmuWiz v0.8.0-alpha release notes (unreleased)

**Status: not yet tagged or published.** These notes describe the state of
`main` at the current release candidate. The currently published release
remains [`v0.7.2-alpha`](v0.7.2-alpha.md) until `v0.8.0-alpha` is tagged.
Feature freeze is active: this document will be finalized, not rewritten,
before tagging.

EmuWiz v0.8.0-alpha ("Alpha 2.0") adds derived, preservation-first frontend
views (Generic and RomM), a whole-library Repair Center with review/apply/
history/undo and duplicate quarantine, and a centralized media-recognition
layer, alongside a run of DAT-verification-engine hardening (7z member
verification, CHD identity evidence, dependency-aware set completeness,
optional RAR5 verification).

## Highlights

### Frontend Profiles / RomM Library Views

- **Library Views**: named, symlink-based organized folder trees generated
  from your existing catalogued archives, in either a `Generic`
  (`{platform}/{filename}`) or `Romm` (`roms/{slug}/{filename}`) layout.
  A view is planned (preview) and applied (create/repair/remove symlinks)
  as two explicit, separately reviewable steps.
- **Preservation-first, always derived.** A Library View never copies, moves,
  renames, or modifies an original archive - every entry is a symlink back
  to the real file in its real source folder. Removing a view, or an entry
  from it, only ever removes the generated symlink, never the source.
- **Stale-preview invalidation.** A view's cached preview is invalidated
  whenever the inputs it was built from change (selected sources, platform
  filter, profile/policy), so Apply can never act on a plan that no longer
  matches the view's current configuration.

### Library View Apply safety hardening

- **Destination containment.** Apply's Create/Repair/RemoveStale/
  managed-directory-cleanup paths now verify, via canonicalization, that
  every path they touch resolves inside the view's real destination root -
  closing a symlink-escape class of bug where a pre-existing symlink planted
  at (or beneath) the destination root could redirect a write outside it,
  including into a source or preservation directory.
- **Fresh source reproof.** Immediately before Create/Repair, Apply
  re-verifies the source target still exists, is still a plain file (not a
  symlink), still resolves inside its registered source root, and - where the
  catalogue recorded a size/mtime fingerprint - still matches it. A plan is
  never applied against a target that changed or disappeared since it was
  planned; Apply fails closed rather than creating a dangling or
  mismatched link.

### Centralized media recognition

- **One media registry**, not three independently maintained extension
  lists. Scanning, rescanning, and the filesystem watcher all now derive
  "does EmuWiz recognise this extension, and how is it persisted" from the
  same table - closing a real drift where the watcher had silently fallen
  behind scanning (`.gcz`/`.rvz`/`.wbfs`/`.ciso` were scan-recognised but
  watch-blind).
- **C128 `.d64`/`.g64` support.** Loose Commodore floppy-disk images are
  catalogued directly (no archive wrapper). Media recognition is
  deliberately kept separate from platform assignment: recognizing a `.d64`
  file is not the same question as deciding which Commodore platform it
  belongs to, and folder/source evidence still resolves that ambiguity
  exactly as it already did for every other shared extension.
- **Neo Geo CD `.chd` recognition and the `neocdz` folder alias.** `.chd`
  (MAME's Compressed Hunks of Data format) is now a recognised media
  extension, cataloguable for Neo Geo CD, Sega CD, arcade, and redump-style
  CD/DVD collections. `neocdz` - the real MAME driver name and a real-world
  folder convention - was added to Neo Geo CD's folder aliases after a
  smoke test against an actual collection surfaced the gap. `.chd` alone
  remains deliberately never sufficient platform identity by itself; a
  `.chd` in an unrecognised folder resolves no platform at all.

### Trusted local DTD diagnostics

- A Logiqx DAT's `DOCTYPE` external identifier is now resolved against a
  short, explicit, local-only allowlist, replacing the previous blanket
  "DOCTYPE accepted as inert text" note with real provenance diagnostics
  (`trusted_dtd_resolved`, `trusted_dtd_unavailable`, `doctype_none`,
  `unsafe_or_unknown_doctype_ignored`). Resolution never performs a network
  request, never opens a `file://` or other URI scheme, never accepts an
  absolute path, drive-letter path, UNC path, or `..` traversal, and never
  claims DTD schema validation occurred - it only ever adds provenance to
  what the parser already treated as safe, inert text.

### Whole-library Repair Center, GUI Repair Scan, and duplicate quarantine

- **Repair Center core**: a transaction-based, journal-checkpointed rename
  executor with no-clobber (`RENAME_NOREPLACE`) semantics, crash-safe
  recovery/reconciliation, and rollback - built once and reused by every
  repair path rather than a second mutation system per feature.
- **Whole-library repair planner** (CLI `repair scan`/`plan`/`apply`):
  audits a library against a DAT catalogue and turns the result into a
  categorised, non-executable report plus a validated, executable rename
  plan - safe renames only ever come from the hardened DAT rename rules,
  never invented.
- **Repair Review GUI**: preview a saved (or freshly scanned) repair plan,
  filter/select Safe proposals, and apply exactly the selection you
  confirmed. Apply always re-scans and fully re-proves the entire saved
  plan against current, live state before touching anything - a stale or
  tampered plan can never be replayed.
- **GUI "Scan library for repairs."** The GUI can now run the same
  whole-library repair scan the CLI already had, in the background (the UI
  stays responsive), and load a successful result directly into Repair
  Review - reusing the existing `run_library_scan`/`build_library_repair_report`
  engine path, never a second planner. A failed scan never leaves a stale
  or half-loaded plan, and never touches ROM files.
- **Skipped-file explanations.** Where a scan previously only reported
  aggregate "N skipped (unsupported extension)" / "N skipped (ambiguous
  platform)" counts, the GUI can now show a bounded, drillable list of the
  actual skipped paths and reasons (capped at 1000 retained entries per
  scan, with truncation reported honestly, never silently hidden) alongside
  the still-exact aggregate counts.
- **Repair History and rollback.** Every apply/rollback is recorded, with
  safe undo available from history for anything still reversible.
- **Duplicate content evidence, quarantine, and review.** Byte-identical
  duplicates found during a repair scan can be safely quarantined (moved
  into a `.emuwiz-quarantine` folder inside their own trusted root, never
  permanently deleted) with an objective, content-proven survivor
  selection; groups with no unique objective survivor are marked
  needs-review rather than guessed at, and quarantine moves are reversible
  through the same Repair History/Undo path as any other repair.

### Rename transaction restart/recovery reconciliation fix

- A transaction whose every entry had already durably settled (renamed and
  confirmed) could, in a narrow window, be left showing an overall
  `Applying` status after a restart if the final journal write that would
  have recorded `Applied` failed to land - even though nothing was actually
  incomplete. Recovery now reconciles the transaction-level state from its
  already-durable entry states using the exact same completion rule the
  executor's own happy path already applies, and fails closed (leaves the
  status unchanged) whenever that outcome cannot be proven from the
  entries' own recorded state. The GUI's fresh-restart load path and its
  already-open-page recovery refresh now share this reconciliation, so the
  two can no longer disagree.

### DAT verification engine (merged across this range)

- Bounded 7z member DAT verification (groundwork; not yet a production
  audit path in the same sense as the ZIP member path).
- CHD v5 header identity reading and CHD disk identity evidence.
- Dependency-aware (Stage 2d) set completeness, conservative Stage 1/2 set
  completeness semantics, and nested software-list DAT member indexing.
- Safe outer-archive renaming.
- Optional, fd-pinned RAR5 verification (opt-in provider; closes several
  fail-open integration paths in the same range).
- A No-Intro/SMS DAT semantics fix (verified status and `cloneofid`
  handling).

## Real-world validation performed this cycle

- **C128**: a real `/mnt/usbdrive/games/c128` collection (23 `.d64` + 8
  `.g64`) scanned, catalogued, and applied through a RomM-profile Library
  View end to end - 31 symlinks created, zero broken links, every target
  resolving inside the real source root, zero source-file mutation, and a
  second Apply confirmed idempotent (0 unnecessary Create/Repair/Remove).
- **Neo Geo CD**: a real `/mnt/usbdrive/games/neocdz` collection (90 `.chd`
  + 2 `.zip`) validated the same way - 92 symlinks, zero broken links, the
  `neocdz` folder-alias fix confirmed against the real collection that
  surfaced the gap in the first place.
- **RomM SMS**: an end-to-end RomM identity/Library View validation pass
  against a real Master System catalogue.

## Known limitations

- **ES-DE frontend output is not implemented.** `FrontendProfileKind::EsDe`
  exists as a typed placeholder and is refused (fails closed) rather than
  silently falling back to `Generic` output.
- **RomM server-ID validation is deferred.** A Library View's RomM identity
  cache is accepted from any server rather than cross-checked against the
  currently configured RomM source's validated server ID - a deliberate,
  documented deferral (checking it correctly would require network-capable
  endpoint validation, not a pure local-file read), not an oversight.
- **CUE/BIN, GDI, and M3U grouping are not implemented.** The media
  registry recognises single files only; multi-file disc/playlist grouping
  is out of scope for this release.
- **A `.chd` extension alone is never identity proof.** It is shared
  weak/ambiguous evidence across several disc-based platforms; a `.chd`
  outside a recognised folder resolves no platform at all, by design.
- **Generated/derived views never replace preservation originals.** A
  Library View is symlinks only - deleting a view's destination folder, or
  removing entries from it, never touches (and cannot touch) the original
  archives it points at.
- **No claim of broad Libretro extension support.** The media registry
  covers the specific formats named above; it does not attempt to be a
  general-purpose Libretro/RetroArch extension database.
- **v0.8.0-alpha has not been published.** No tag, no GitHub release, no
  downloadable artifact exists for it yet. Until it is tagged, install
  [`v0.7.2-alpha`](v0.7.2-alpha.md) or build from `main` at your own risk.
