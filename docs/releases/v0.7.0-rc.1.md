# ArchiveFS v0.7.0-rc.1 release notes

Status: historical release candidate. Commit
`113b508bd6839309cfd9e25d054094cc27112860` passed real Sunshine desktop GUI
testing and was approved for promotion to v0.7.0. These notes preserve the RC
state; see [`v0.7.0.md`](v0.7.0.md) for the final release.

## Overview

ArchiveFS v0.7 brings evidence-based platform detection, a platform-first
Gamer View, verified PS2/GameCube/Wii identity, safer emulator profile
resolution, transaction-backed cheat workflows, expanded Doctor diagnostics,
and the optional browse-only BSFree Archive source. Source collections remain
read-only; network and emulator writes require explicit feature-specific user
actions.

## Install and first run

Download the candidate archive and adjacent `.sha256` file supplied for manual
testing. Verify before extracting:

```sh
sha256sum -c archivefs-v0.7.0-rc.1-x86_64-linux.tar.gz.sha256
tar -xzf archivefs-v0.7.0-rc.1-x86_64-linux.tar.gz
cd archivefs-v0.7.0-rc.1-x86_64-linux
./archivefs-cli --version
./install.sh
```

The installer defaults to `~/.local/bin`, uses no `sudo`, and does not replace
an existing ArchiveFS configuration. For a first run:

1. Copy/edit `config.toml.example` under `~/.config/archivefs/config.toml`.
2. Set absolute `source_folders` and a separate `mount_root`.
3. Run `archivefs-cli config-check` and `archivefs-cli doctor`.
4. Run `archivefs-cli library-scan`, or open the GUI and use its explicit scan.

No source scan, provider download, cheat installation, or emulator launch is
automatic on first run.

## Upgrade from v0.6 development state

Stop ArchiveFS and back up `~/.local/share/archivefs/library.sqlite3` plus any
managed cheat/history state before upgrading. Existing source configuration,
manual platform assignments, Dolphin choices, and cheat-source settings are
retained. Opening the catalogue applies forward-only migrations through schema
6; migrations are exactly `0001` through `0006`. Older binaries cannot open a
schema-6 database, so rollback requires restoring the pre-upgrade copy rather
than editing SQLite metadata.

After upgrading, run `archivefs-cli doctor --findings` and rescan sources whose
stored platform findings predate the canonical registry.

## Gamer View and platform confidence

Gamer View is the default platform-first library view. The fixed-height
platform shelf supports Previous/Next controls, mouse wheel, trackpad, drag,
arrow keys, and TV/Moonlight navigation without overlapping the game list.
Advanced View remains available for Sources, Doctor, History & Logs, and
technical details.

Platform evidence is reported as:

- **Confirmed**: conclusive evidence, or independent strong evidence that
  explicitly agrees.
- **Probable**: one strong but non-conclusive signal.
- **Ambiguous**: credible evidence conflicts or ties.
- **Unknown**: no supported evidence settles a platform.

`DetectionEvidence.conclusive` matters: a structurally valid FAT12 `.st` image
is plausible Atari ST media but is not unique to Atari ST. It reaches Confirmed
only with agreeing folder evidence. A valid Pasti `.stx` container is
Atari ST-specific and can be conclusive by itself. Generic `.dsk`, `.bin`, and
`.iso` extensions remain ambiguous without platform-specific evidence.

Signature reads through symlinks are opt-in through trusted-root-aware paths.
Both the link and canonical target must stay within configured trusted roots;
escaping, broken, or looping links are refused with typed diagnostics.

## Cheats & Mods

PS2, GameCube, and Wii GameHacking workflows require verified local identity.
Filename candidates are never promoted to verified identity. Browser-assisted
imports accept saved/pasted reviewed content without live GameHacking access;
Cloudflare challenge pages are rejected and never poison caches.

The validated New Super Mario Bros. Wii/SMNE01 import produces:

- 121 parsed cheats
- 98 supported cheats
- 23 blocked or unknown cheats

Supported Action Replay and Gecko entries can use the existing Dolphin
GameSettings transaction flow. Unsupported, unlabelled, placeholder-bearing,
master-code-dependent, or revision-mismatched entries remain preview-only.
GameCube and PS2 retain their native provider/install formats and the shared
preview, atomic-write, verification, History, managed-only removal, and Undo
pipeline.

Dolphin discovery supports native installs, Flatpak's data-tree profile, and
AppImage/custom `-u`, `--user`, and `--user=<path>` roots. A verified running
profile is labelled Running; an explicit manual choice is labelled Selected.
Multiple credible stopped profiles require a choice instead of a hidden
default.

## Sources and BSFree Archive

BSFree appears under Cheats → Sources and remains unconfigured until the user
explicitly downloads or imports the third-party SQLite database. ArchiveFS
validates the documented source hash/schema, stores its own immutable copy,
and opens it read-only and query-only. It provides bounded game search and
lazy code pagination across 44 mapped systems and 11 device classifications.

BSFree results retain upstream IDs, attribution, device, section, author,
notes, raw code, and the local database fingerprint. Matching is based on
platform/title/version evidence, not exact ROM identity, so multiple revisions
remain Ambiguous. Stage 1 is labelled **Browse only** and has no Install action.

## Doctor

Doctor combines setup findings, environment/storage/profile checks, and
managed-cheat diagnostics. Historical terminal mount attempts are grouped and
labelled as historical rather than hundreds of current emergencies. Findings
that have no safe, exactly bound repair remain read-only. Stage 1B repairs show
the exact resource, require confirmation, verify afterward, and are recorded in
History; they cannot execute arbitrary paths or commands.

Useful commands:

```sh
archivefs-cli doctor
archivefs-cli doctor --findings
archivefs-cli database-check --json
archivefs-cli platform-detect /path/to/game.st
archivefs-cli cheats source bsfree status --json
archivefs-cli cheats source bsfree search --platform NES --title MARIO --json
```

BSFree download/import commands are explicit. Ordinary browsing performs no
network access.

## Safety

- Archive and game-image sources are never modified.
- Atari disk inspection is bounded to 64 KiB total, 1 KiB per read, 32 KiB
  maximum offsets, a 4 MiB raw-image cap, and a 32 MiB STX cap.
- Checked arithmetic and bounded record counts prevent header-controlled
  allocation or traversal.
- Emulator writes require an exact destination preview and confirmation, use
  atomic replacement and backup where applicable, and verify the live target.
- BSFree is optional third-party historical community data; its database-content
  licence is not established and ArchiveFS does not bundle or republish it.

## Known limitations

- BSFree is browse-only and title matching may return ambiguous revisions.
- Malformed/cracked Atari ST `.st` images may remain Probable.
- ZIP-contained identity, CHD, RVZ, and generic BIN identity remain incomplete.
- RomM integration is not included.
- Some emulator-specific cheat formats and destinations remain unsupported.
- Stored historical platform findings may require a rescan.
- Symlink signature scanning remains opt-in through trusted-root-aware paths.
- ArchiveFS is Linux-first prerelease software; complete manual desktop QA is
  still required before a final v0.7 tag.
