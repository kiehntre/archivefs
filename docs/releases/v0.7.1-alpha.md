# EmuWiz v0.7.1-alpha release notes

EmuWiz v0.7.1-alpha ("Alpha 1.1") is a stabilization release on top of
`v0.7.0`. This release-prep work itself (the version bump, changelog, and
documentation pass that produced this document) introduces no new
implementation. Alpha 1.1 *as a release*, however, does ship real
user-facing functionality that merged to `main` between v0.7.0's tag date
and this release-prep work: RomM identity-provider integration (with
cover-art and platform-artwork workflows), a Cheat Sources GUI, a DAT
Sources GUI, DAT rename planning/apply, DAT Games-only filtering,
classifier-version enforcement on apply, BSFree GameCube and Wii cheat
install, installer ownership hardening, first-run/empty-state polish, and
EmuWiz desktop integration. See [`CHANGELOG.md`](../../CHANGELOG.md) for the
full, categorized list.

## Highlights

- **RomM identity-provider integration.** A read-only RomM client and
  adapter with token-based auth and capability inspection
  (`crates/archivefs-core/src/identity_source/romm/`), a CLI surface
  (`crates/archivefs-cli/src/romm_identity.rs`), and GUI configuration,
  browsing, and selected-game identity flow
  (`crates/archivefs-gui/src/romm_source.rs`, `romm_config.rs`,
  `romm_browse.rs`, `romm_game.rs`). Includes RomM cover artwork in Gamer
  View and managed platform-artwork import.
- **Cheat Sources GUI and DAT Sources GUI.** Registry, validation, and
  read-only audit surfaces for both cheat and DAT sources
  (`crates/archivefs-gui/src/cheat_sources_page.rs`,
  `crates/archivefs-gui/src/dat_sources_page.rs`), including cheat-source
  health, and DAT warning presentation, audit progress, and deterministic
  cancellation.
- **DAT rename planning and apply.** A read-only plan is built from an audit
  and the effective matching policy (`crates/archivefs-core/src/dat/rename_plan/`),
  then an explicitly approved subset can be applied through a gated,
  journal-backed transaction executor
  (`crates/archivefs-core/src/dat/rename_apply/executor.rs`). Preflight runs
  once for the whole batch and again immediately before each individual
  rename; the journal is written durably before any mutation; renames use a
  no-clobber primitive and are confirmed against the filesystem before being
  marked `Applied`; a crash mid-batch leaves a recoverable journal state.
- **Classifier-version enforcement.** `apply_transaction` and
  `build_transaction` both reject a plan whose `classifier_version` does not
  match the current classifier before any journal write or mutation,
  surfacing "regenerate the plan" instead of silently applying a stale plan.
- **DAT Games-only content filter.** Structured `category`/`type`/`content_type`
  trust is now explicitly scoped to No-Intro DATs behind a safe, GUI-selectable
  policy option.
- **BSFree GameCube and Wii cheat install.** Supported BSFree GameCube codes
  apply through the existing Dolphin adapter
  (`crates/archivefs-core/src/patch_manager/bsfree_gamecube.rs`); a later,
  distinct addition generalises the same dedup analysis to a verified-subset
  Wii install (`crates/archivefs-core/src/patch_manager/bsfree_wii.rs`).
- **First-run and empty-state polish.** A genuinely missing config is now
  treated as first-run rather than an error, with a first-run hint instead
  of a bare OS error (`crates/archivefs-cli/src/main.rs`).
- **Installer ownership hardening.** `install.sh` now tracks ownership of
  installed assets by SHA-256 content identity rather than mtime/pathname
  heuristics, with safer backups and a stricter manifest parser that rejects
  content following the manifest's end marker.
- **EmuWiz desktop integration.** A Linux application icon and
  `io.github.kiehntre.emuwiz` desktop launcher entry.
- **Documentation reconciliation.** `README.md`'s install walkthrough,
  `docs/security.md`, `SECURITY.md` (DNS-rebinding and redirect wording), and
  this changelog were brought in line with current shipped behavior as part
  of this release-prep pass.

## Install

```sh
VERSION=v0.7.1-alpha
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/archivefs-$VERSION-x86_64-linux.tar.gz
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf archivefs-$VERSION-x86_64-linux.tar.gz
cd archivefs-$VERSION-x86_64-linux
./emuwiz-cli --version
./install.sh
```

The installer is per-user, uses no `sudo`, and does not overwrite an existing
configuration.

## Upgrade from v0.7.0

No database schema change accompanies this release (schema remains version 6).
Existing configuration, provider settings, DAT source registrations, and
cheat-source settings are preserved. If you have a manifest from an `install.sh`
run predating the ownership-hardening change (#38), rerun `./install.sh` (add
`--replace-foreign` only if you intend to take ownership of files it flags as
foreign) - see the manual smoke checklist for the exact upgrade path this
covers.

## Legacy compatibility (unchanged)

This release makes no changes to legacy compatibility surfaces. `archivefs-core`,
`archivefs-cli`, and `archivefs-gui` remain the crate/package identities;
`archivefs-cli`, `archivefs-gui`, and `emuwiz-gui` remain installed binary
aliases; `~/.config/archivefs` and `~/.local/share/archivefs` remain honoured
as fallback config/data directories when no `emuwiz`-named directory exists
yet (`crates/archivefs-core/src/app_dirs.rs`); `ARCHIVEFS_*` environment
variables and the `archivefs-v*` release artifact naming scheme are unchanged.

## Known limitations

Unchanged from v0.7.0 (see [`docs/releases/v0.7.0.md`](v0.7.0.md#known-limitations)).
Additionally, and explicitly out of scope for this release: ZIP-member
verification, NES header normalization, CHD verification, B2/split-archive
grouping, wrong-platform diagnostics, and 7z/RAR support remain research-only
(`docs/research/`) and are not implemented.

## Manual validation still required

have run against this branch; the five manual smoke journeys listed there
