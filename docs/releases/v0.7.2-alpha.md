# EmuWiz v0.7.2-alpha release notes

EmuWiz v0.7.2-alpha ("Alpha 1.2") adds archive-aware DAT verification while
keeping archive handling read-only and bounded.

## Highlights

- **ZIP-member DAT verification.** DAT audits can decode and hash Stored and
  Deflate members inside ZIP archives. Results preserve the outer path,
  member index, raw member-name bytes, and a safe display name. Duplicate
  names remain distinct by index.
- **Fail-closed archive safety.** ZIP preflight validates archive structure
  and packed-data ranges before decoder construction. Member counts, logical
  bytes, per-run work, and decompression ratios are bounded; hashing is
  cancellable, consumes accepted members through CRC validation, and detects
  outer-file replacement during a pass.
- **Evidence remains non-mutating.** Archive-member matches are separate from
  flat physical audit entries and cannot produce rename proposals. EmuWiz
  does not extract, rewrite, rename inside, or recompress ZIP archives.
- **Archive groundwork.** The shared format-neutral archive-member contract
  and hardened read-only 7z reader prepare later formats without enabling 7z
  as a production DAT audit path in this release.
- **DAT fidelity.** Indexed ROM evidence now retains `status` and `merge`, and
  DAT size attributes accept decimal or `0x`/`0X`-prefixed hexadecimal values.
- **CI efficiency.** Pull-request branches no longer receive a duplicate
  branch-push CI run; main pushes and manual dispatch remain covered.

## Install

```sh
VERSION=v0.7.2-alpha
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/archivefs-$VERSION-x86_64-linux.tar.gz
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf archivefs-$VERSION-x86_64-linux.tar.gz
cd archivefs-$VERSION-x86_64-linux
./emuwiz-cli --version
./install.sh
```

The installer remains per-user, uses no `sudo`, and preserves existing
configuration. Existing ArchiveFS package names, executable aliases, legacy
config/data paths, environment variables, database schema, rename journals,
and `archivefs-v*` artifact naming remain compatible.

## Known limitations

- ZIP-member verification supports Stored and Deflate only. Encryption,
  nested archives, malformed input, and unsupported codecs are refused.
- Inner-member rename, archive rewriting, recompression, and set-completeness
  claims are not implemented.
- 7z production DAT integration, RAR, CHD verification, and NES header
  normalization remain future work.
